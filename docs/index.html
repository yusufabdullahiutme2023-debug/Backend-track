Tech Stack

Every layer chosen for simplicity, performance, and zero-maintenance hosting.

⚡ FastAPI + Pydantic

High-performance async Python framework with strict request/response validation and auto-generated OpenAPI docs.

🐘 PostgreSQL (Neon)

Relational persistence with serverless Postgres. Direct parameterized SQL via psycopg2 — no N+1, no magic.

🔐 JWT Auth + bcrypt

OAuth2 password flow issuing signed HS256 tokens (1-hour expiry); passwords hashed with bcrypt via passlib.

🚦 Redis Rate Limiting

Per-user request throttling on Upstash Redis using atomic INCR + TTL windows — configurable via environment.

🐳 Docker

Single lightweight image (python:3.14-slim). Runs identically in CI, on Render, and on any laptop.

🔁 GitHub Actions CI/CD

Every push: build the image, spin up a Postgres 16 service container, boot the API, and run a live end-to-end smoke test.

CI/CD Pipeline

Quality gates run automatically on every push and pull request.

1

Build the Docker image

GitHub Actions builds the same image that ships to production — no "works on my machine."

2

Spin up Postgres 16 service container

A real database with health checks, matching the hosted Neon environment.

3

Boot the API container

The app runs with the same environment-variable contract used in production.

4

Live end-to-end smoke test

Register → login → create message with Bearer token → verify it appears in the list. The build fails fast if any step breaks.

Try It Yourself

Three requests and you've exercised the whole auth + data flow.

# 1. Register
curl -X POST "https://backend-track-nz8c.onrender.com/register?username=alice&password=secret123"

# 2. Log in — returns an access token
curl -X POST https://backend-track-nz8c.onrender.com/token -d "username=alice&password=secret123"

# 3. Create a message (replace TOKEN with your access_token)
curl -X POST https://backend-track-nz8c.onrender.com/messages \
  -H "Authorization: Bearer TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"sender":"alice","text":"what is the price"}'
